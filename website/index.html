Scheduling fundamentals

Four policies, different trade-offs

Processes may alternate between CPU bursts and blocked I/O waits. SJF and Priority are non-preemptive per CPU burst; Round Robin is preemptive at quantum boundaries.

FCFS

First Come, First Served runs processes in arrival order. It is straightforward, but a long job can make later jobs wait.

SJF

Shortest Job First selects the shortest burst among processes that have arrived. This version is non-preemptive and may delay long jobs.

Priority

Selects the available process with the smallest numeric priority value. This version is non-preemptive; starvation is possible in general.

Round Robin

Shares CPU time in turns up to a configurable quantum. Smaller quanta can improve early response but add more scheduling switches in real systems.

Explainable selection

From workload features to a policy

The adaptive demonstration extracts summary features, classifies the workload using nearest-centroid distance, then applies a fixed, visible mapping. It demonstrates policy selection—not proof that the selected policy is best.

1 · GenerateMake deterministic synthetic processes with arrivals, CPU bursts, and priorities.
2 · ExtractMeasure mean CPU burst, burst variability, short-burst fraction, and the ratio of simulated I/O wait to CPU service.
3 · ClassifyCompare the feature vector to labelled synthetic class centroids.
4 · SelectMap the predicted workload class to a scheduling policy.

Scope and next steps

What this project does—and does not—model

Current limitations

  • Both demos are simulations; neither changes the Windows/Linux kernel or measures live machine scheduling.
  • The browser demo models I/O waits as simulated blocked intervals; it does not perform real device I/O or change the operating-system kernel.
  • The classifier is a small educational nearest-centroid model trained on synthetic labels. No measured accuracy is claimed.
  • Results depend on generated inputs and configuration; adaptive selection is not guaranteed to beat every fixed policy.

Possible future work

  • Model explicit I/O wait and alternating CPU/I/O bursts.
  • Evaluate classification on held-out workloads and report a confusion matrix.
  • Study fairness, starvation, context-switch overhead, and multiple random seeds.
  • Compare adaptive selection against every fixed policy using the same inputs.
